# Repository Guidelines

Contributor guide for `eventify_front_end`, the React + TypeScript front end for Eventinos (Vite, Tailwind CSS v4, shadcn/ui, Redux Toolkit, React Router, Zod, i18next).

## Project Structure & Module Organization

- `src/api/` — Axios API modules per domain (`authApi.ts`, `eventsApi.ts`).
- `src/app/` — layout shell (`_layout.tsx`, `header.tsx`, `footer.tsx`, `navBar.tsx`).
- `src/components/` — `ui/` shadcn/Radix primitives, `shared/` reusable components, `partials/` feature components, `charts/` dashboard charts.
- `src/pages/` — route pages; `src/router/router.tsx` — React Router definitions.
- `src/store/` — Redux store; `store/features/<feature>/` contains `.actions.ts`, `.reducer.ts`, `.types.ts`.
- `src/schema/` — Zod schemas; `src/lib/` — utilities and the shared Axios client; `src/i18n/locales/` — en/fr/ar/eg translations; `public/` — static assets.

## Build, Test, and Development Commands

- `npm run dev` — start the Vite dev server with HMR.
- `npm run build` — type-check (`tsc -b`) then build into `dist/`.
- `npm run lint` — run ESLint across the repository.
- `npm run preview` — serve the production build locally.
- `docker compose up` — run the services and nginx defined in `docker-compose.yml`.
- Copy `.env.example` to `.env.local` and fill in `VITE_BACKEND_URL`, `GOOGLE_MAPS_API_KEY`, `VITE_GOOGLE_MAPS_MAP_ID`, `VITE_APP_ENV`.

## Coding Style & Naming Conventions

- TypeScript `strict` mode; flat ESLint config (`eslint.config.js`) extends `@eslint/js`, `typescript-eslint`, `react-hooks`, and `react-refresh`.
- Use 2-space indentation and import from `src/` via the `@/` alias.
- Components: PascalCase files/exports (`EventAddForm.tsx`); hooks: `useXxx.ts`; APIs/utilities: camelCase (`eventsApi.ts`, `apiClient.ts`).
- Redux features follow `<feature>/.actions.ts`, `.reducer.ts`, `.types.ts`.
- Style with Tailwind utility classes; keep new shadcn/ui primitives in `src/components/ui`.

## Testing Guidelines

No automated test framework is configured. Verify with `npm run build` and manual checks in `npm run dev`; use `src/pages/ErrorHandlingTestPage.tsx` for error-boundary checks. If adding tests, use Vitest + React Testing Library.

## Commit & Pull Request Guidelines

- CI auto-bumps the app version on pushes to `main` based on commit prefixes: `breaking:`/`major:` → major, `feat:`/`feature:`/`minor:` → minor, anything else → patch.
- Keep commits short and imperative (e.g., `add the logo`, `fix the language switcher`); automated commits use `chore: bump version to x.y.z [skip ci]`.
- Open PRs against `main` with a summary, manual test steps, and screenshots for UI changes; `main` deploys automatically.

## Security & Configuration Tips

- Never commit `.env` (gitignored) and keep real keys out of `.env.example`.
- `src/config/version.ts` is auto-generated by the version-bump workflow — do not edit it manually.
- Add UI strings to `src/i18n/locales/*.json` instead of hardcoding text.
